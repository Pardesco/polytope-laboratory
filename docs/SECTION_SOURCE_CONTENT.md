# Source-owned content on complete ordinary-cell sections

The primary Stella [cross-section workflow](https://software3d.com/Manual/Slice.php) describes rank loss: edges become cut vertices, faces become one or more cut boundaries, and 4D cells become one or more section faces. Its [text workflow](https://software3d.com/Manual/Text.php?prod=Great) supports limited formatted text and screen-aligned placement. This feature implements those ownership relations on the application's explicit complete ordinary-cell section domain.

Formatted source cell text appears once per connected section face region. Disconnected components retain the same source cell ID and distinct component IDs. A region with holes has one text occurrence, anchored on a real visible display triangle rather than in its hole. Coplanar source cells retain one occurrence per surviving face sheet. Source face text appears on every actual cut boundary; original edge text appears at its actual cut vertices. Original vertex text appears only when that original vertex survives on the plane. Elements wholly outside the plane have no occurrence.

The native `metadata.sectionSourceContent` version-1 descriptor binds the full source using the existing portable annotation SHA-256 encoding. It lists source kind/index, target kind/IDs, component ownership, section embedding and verified whole-face sheets. The UI checks the original incidence, cut edge parameters, reconstructed coordinates, plane basis, complete region records and ordered whole-face cycles. Sprite receipts retain all original owner IDs. Nothing is welded, renumbered as a source element, convexified or transferred into the source document.

PNG is available only on a genuinely surviving whole affine original face. Its complete ordered corners, source tangent frame, orientation and raw source-face alpha are retained. A PNG requested on a transverse or absent face explicitly refuses preparation and capture. Face text accompanying a supported PNG still follows the cut boundaries; it is not silently omitted or guessed onto a new cell section face. A mathematically empty section has no text occurrences and can be captured as empty; requested PNG still refuses.

Live derived views, main capture, independent saved tour layers and saved section-depth animation share this mapping. The current saved plane/fill rule, full source attributes, annotations, notes, units, cancellation and renderer ownership remain fenced. Moving the plane reconstructs native geometry and correspondence at every actual sampled depth. This has no dual-morph interpolation dependency.

The original annotation document, source notes, units and geometry remain unchanged. Promoting a section keeps the existing detached annotation archive and creates an empty new-source annotation document; this feature does not infer a permanent transfer from a many-to-many live correspondence.

Limits remain explicit: complete ordinary embedded source cells only; at most 100000 native correspondence occurrences and 4096 visible label occurrences, with bounded source/descriptor JSON. Section canvases share the existing 16 Mi-pixel budget through bounded per-entry resolution. Surface-only and generalized star-cell section paths remain unsupported for source content. No external font or markup DOM is loaded.
