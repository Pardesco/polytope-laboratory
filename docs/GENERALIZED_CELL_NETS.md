# Generalized 4D whole-cell nets

The source domain now includes globally nonconvex intrinsic 4D cell shells with independently valid full convex 3D source cells. Every supplied cell and ordered face cycle remains intact. Each source face joins exactly two distinct cells. The shell must be orientable, with circular edge links and connected spherical vertex links; its global topology is not required to be spherical. Incidence-disjoint closed components are allowed. Geometry/incidence qualification uses the actual source; it never creates a replacement hull or simplifies faces.

Each cell must span an affine 3D hyperplane. Its faces must be simple convex planar ordered cycles, cover its entire distinct supporting facets, close along every edge, and form a connected Euler-two boundary. Every supplied vertex must lie on the inward side of every cell facet. These tests validate the supplied convex cell, independently of whether the full 4D shell is convex. Concave cells, star cells, coplanar partial/duplicate facets, open/nonmanifold shells, nonorientable incidence and unresolved rank are explicitly refused.

Cell normals propagate through oriented incidence of actual shared source faces. They do not point toward or away from the whole-source centroid. Rigid 4D rotations unfold cells into the same intrinsic 3D chart around their matching 2-face, including already coplanar neighboring cells (zero rotation) and opposite coorientations (a half-turn in the face-normal complement). Cuts, joining, reattachment, rigid component placement, source face/vertex selection, display shrink and original model units use the existing controller and Viewer. Source-cell distances and all joined-face vertices are checked after placement.

The established convex route remains unchanged. A lazy branch in `engine.cell_nets.cell_net` is used by existing protocol jobs, edits and native project reconstruction. Frozen importer files need no changes. Saved history is source-ID/fingerprint bound; a missing cached layout restores its current connections and placements without truncating redo. Held native results are fenced against source, units, notes, view/state, history and cancellation changes. Existing annotation/capture/tour whole-cell mapping continues to use the intact source owner records. No new application mode or protocol allowlist entry is needed.

The [primary Stella manual, section 15.8](https://www.software3d.com/Manual/Net4D.php) describes full-cell 3D nets, matching source faces/vertices, reattaching a cell with its dependent subtree, shrink, persisted edits and separate-cell starts. It explicitly keeps complete cells and ignores intersections between arranged cells. This extension follows that same baseline: arranged-cell collisions and source global self-intersections are not checked, removed or repaired. No overlap-free layout, unrestricted generalized-cell coverage, printable physical 4D model or animation-fold collision avoidance is claimed.

Approximate float64 limits: 1,024 complete cells, 256 facets and 256 vertices per cell, 128 vertices per face, 100,000 source face-boundary vertices, and 20,000 cell-vertex incidences. Predicates and rank/support decisions are scale-normalized with the existing tolerance.

Independent targeted fixtures use a literal 4-simplex boundary dented inward by four supplied tetrahedral cells. A cell hyperplane has source vertices on both sides, proving the whole source is genuinely nonconvex. A coplanar facet subdivision checks the formerly singular hinge case. Checks retain all cell/face IDs and cycles, every metric distance and shared-face join, cut/move/join/reattachment, native reconstruction of tampered cached geometry, saved history/notes/RGBA, owner refusals and the unchanged convex route. A prism of an independently dented 3D tetrahedron exercises explicit refusal of nonconvex cap cells. Controller checks cover saved layout restoration and held-result source/unit/history fences. The fresh stage also checks actual protocol jobs and actual generalized face-net cached-layout reopen.
