# Source-region cell diagrams and inaccessible-cell filling

The Construct panel gains **Stellation cell / dependency diagram**. Evaluate the existing source facial-plane arrangement, then build the cell diagram. It shows individual enclosed region IDs, the innermost core below outer layers, and links between actual shared full facets. Source facial-plane IDs and exact region facet IDs are retained in every native link. This is an individual-region workflow, not a claim that arbitrary region sets preserve the seed symmetry.

The [Stella manual](https://www.software3d.com/Manual/Stellation.php), sections 11 and 11.1, documents cell selection, support/layer selection and inaccessible-cell filling. The author's [Stella: Polyhedron Navigator paper](https://software3d.com/PolyNav/PolyNavigator.php), sections 3.4?3.5, defines facet-adjacent cell graphs and the filling of sealed unselected interior bubbles. These are the primary definitions used here.

Click toggles the selected source region. Ctrl-click (or the action selector) adds the region plus all recursively lower outside-plane-count neighbors. Shift-click toggles all enclosed regions with that same outside-plane count. Dependencies use actual common facets; edge/vertex contacts never create links. Layers are explicitly the number of original signed facial planes whose exterior side contains the region. This is a declared individual-region definition, not an unverified Miller or fully-supported enumeration criterion. A support operation refuses any required clipped, unbounded or facet-uncertain region.

**Fill inaccessible regions** follows the complete observed facet graph through unselected regions, beginning at every unbounded, unresolved, box-touching or unmatched-facet region. Only selectable enclosed regions that this exterior flood cannot reach are added. Actual geometric box contact is checked even when a cached flag says otherwise. Unknown cells therefore prevent a cavity claim. The operation adds selected regions; it never deletes interior topology silently. For an octahedral seed, its eight outer finite cells enclose the original core: filling adds that core. Omitting any one outer cell leaves an opening and adds nothing.

Selection edits have source-bound Undo/Redo stored in `view.stellation.cellSelectionHistory`, with at most 32 before/after steps. The history stores source geometry fingerprint and arrangement SHA-256, refuses obsolete binding and rejects an outside manual selection change at undo time. Existing stellation selection/solid promotion and region-union convex-piece semantics remain the publication path. Native Save/Open retains this selection configuration and source notes. Undo is diagram selection history; future model operations continue to use the ordinary native operation history.

**Export cell diagram SVG** serializes only generated finite SVG elements and text. Metadata records source ID/fingerprint, arrangement hash, selected IDs and the finite domain/uncertainty definitions. The native graph verifies region models and signed half-spaces, real source faces, bounded finite JSON, at most 2048 observed regions, and at most 100000 facet records. Facet candidates are paired only after coordinate and complete ordered-boundary correspondence and opposing half-space side checks. Ambiguous or missing pairs remain exterior seeds.

This workflow supports the existing convex intrinsic-3D facial-plane arrangements. It does not enlarge their observation domain or assert unrestricted stellation enumeration. A completed observation-box partition remains different from an unrestricted stellation result. Graph evidence, boundedness and matching remain float64 approximate with no exact certificate. Source/model attributes, notes, units, workspace and complete relevant arrangement geometry are fenced through asynchronous analysis; camera movement and diagram-plane presentation changes remain independent.
