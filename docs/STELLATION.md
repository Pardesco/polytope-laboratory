# Finite plane-region stellation

Choose a convex 3D model, open **Construct**, and evaluate its facial-plane arrangement. Facial plane IDs refer to the actual source faces, including imported face ordering. Leave the field empty for every face, or enter distinct indices. The observation scale expands an axis-aligned box around the source. The engine can also accept explicit planes `[nx, ny, nz, offset]` through the headless API, meaning `n · x + offset = 0`.

Each full-dimensional region records its signed half-space signature, source planes, convex incidence, centroid, volume, numerical boundedness and whether it touches the observation box. Selectable regions must be bounded and entirely enclosed. The diagram includes clipped and unbounded regions for context; clicking an enclosed polygon changes its incident solid-region selection. SVG export preserves region labels and the declared finite-domain metadata.

**Select all enclosed regions** can construct a nonconvex solid. **Select original seed region** recovers the seed's interior. The selected solid cancels shared internal facets and retains each convex region as mathematical geometry. Promotion opens it in a separate document with source provenance. Its sections retain disconnected components, planar subdivisions and tangent strata without substituting a convex hull. Generalized star imports do not automatically acquire these solid semantics.

The finite union search exhausts subsets of region orbits. Its current explicit criteria are:

- no symmetry constraint, verified signed-axis symmetries, full numerical geometric source symmetries, proper rotations, or a subgroup generated by selected source action IDs;
- optional inclusion of the region inside every original facial half-space;
- optional connectivity through shared full facets.

Only source actions preserving the entire enclosed-region domain participate. For example, the default dodecahedron box clips twelve bounded regions: the acting order falls from 120 to 24. Observation scale 5 encloses all 63 bounded regions and restores order 120. The result records both orders and the restriction. This is completion inside the recorded domain, without a claim that every bounded region outside that domain was found.

Source generator IDs refer to the unrestricted complete geometric result for this source and algorithm version. Enter distinct IDs, or `identity` for the trivial group. The API also accepts setwise entity-stabilizer restrictions through symmetry_options. Selected-source subgroup completeness and unrestricted source order are separate from observation-domain preservation. An octahedron's single coordinate reflection yields one seed orbit and four paired outer-region orbits: 32 subsets produce 16 seed-containing connected candidates, compared with 2 under its full group. Preferences persist; a changed source clears manual generator IDs. See [symmetry definitions](SYMMETRY.md).

The current API limits are 32 planes, a default 2,048 observed regions (configurable up to 8,192), 2,048 pieces in a selected solid, 20 search orbits and 4,096 results (configurable up to 100,000). Arrangement resource failure commits no partial geometry. Search result-limit termination retains candidates and explicitly reports incomplete enumeration. Both predicates and linear-program classifications are approximate.

Verified fixtures include tetrahedral, cubic and octahedral arrangements (15, 27 and 59 observed regions); the octahedron's nine bounded regions form the stella octangula solid with volume 4 in the source coordinates. The 20-plane icosahedron fixture has 703 observed and 341 enclosed regions at scale 3. Its full order-120 group gives eight region orbits, 256 subsets, and 13 candidates under the current seed-inclusion/full-facet-connectivity criteria. This count does **not** identify the classic 59 stellations: that classification uses additional criterion semantics that have not been implemented or independently qualified.

Geometry identity includes retained convex pieces. Projects save the arrangement, selected regions and candidate evidence alongside the source/history. Changing the source or observation domain requires new evaluation; obsolete asynchronous results cannot overwrite a newer domain.

Relevant benchmark descriptions: [Stella stellation manual](https://mail.software3d.com/Manual/Stellation.php?prod=Stella4DPro). The current boundedness solver uses [SciPy linear programming](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linprog.html) with unrestricted coordinate variables; its finite precision classifications are recorded explicitly.
