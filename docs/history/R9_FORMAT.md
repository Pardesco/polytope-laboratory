# R9 mechanical formatting

Date: 2026-11-10. No feature, engine operation, element ID, catalog key, version,
file name or module boundary changed. Changes remain uncommitted for the lead.

## Tools and commands

- Prettier **3.6.2**, invoked through `node node_modules/prettier/bin/prettier.cjs`;
  pinned in `devDependencies`. The lead updates `package-lock.json`.
- Ruff **0.14.10**, invoked through `python -m ruff`.
- `npm.cmd run format` formats eligible files with both tools.
- `npm.cmd run format:check` checks both tools without rewriting files.
- `.git-blame-ignore-revs` has a placeholder comment; the lead adds the commit hash.

Prettier: width 120, single quotes, semicolons, ES5 trailing commas, automatic
line endings, embedded-language formatting disabled to retain literal embedded
HTML/CSS/JS fixture and application strings. Before formatting, the 474 JS files
in `ui`, `desktop` and `scripts` all contained semicolons; 23,588 lines ended in
semicolons, versus 2,203 other nonblank/nonbrace/noncomma/noncolon endings.

Ruff: width 120, quote style `preserve`, automatic line endings, `force-exclude`
to keep explicit file arguments from bypassing exclusions. Only `ruff format`
is used, with no lint fixes or import sorting. Two semicolon-separated assignments
to the Python soft keyword `match` in `engine/vertex_figure_construction.py` were
split onto their own lines so Ruff could parse the otherwise valid source.

The CLI cache location is `.prettier-cache`, outside the shared, read-only
`node_modules` tree. Caching itself remains disabled. Prettier required a second
pass for 11 files before its check was stable.

## Byte inventory and exclusions

[R9_FORMAT_PINS.json](R9_FORMAT_PINS.json) records the pre-format inventory:
manifest-to-source paths, explicit protected sources, historical source snapshot
paths and every existing file beneath the excluded evidence/data trees. The
inventory was made before either formatter ran, by searching `scripts`, `tests`,
`docs/conformance` and `engine` for hashes, digests, pins, frozen inputs, receipts,
media qualification and source-package manifests, then resolving JSON hash maps
and matching hashes to tracked source bytes.

Both `.prettierignore` and Ruff `extend-exclude` retain:

- `data`, `artifacts`, `engine/catalog_data`: original assets, manifests,
  qualification receipts, frozen sources and tools; catalog JSON/OFF bytes stay
  unchanged. `artifacts` contains the frozen 0.21.0 source snapshot.
- `docs`, `tests/fixtures`, `examples`: historical conformance/report evidence,
  source-bound fixtures, media references, sample projects and generated exports.
  Existing documentation, including the lead-owned handoffs and ledger, is untouched.
- `node_modules`, `dist`, `build`, `release`, `third_party_licenses`, environments,
  caches, minified files and named lockfiles: generated or third-party bytes.
- Source paths named by classification implementation evidence, morph-method
  inventories, dense-performance results and retained tool hashes. The explicit
  paths are listed in both configurations and in the inventory.
- Media/common-workflow qualification scripts and their evidence/runtime helpers,
  the source-package script, and the three reserved mounted tests.
- `ui/index.html`: a literal sentence assertion in `tests/help-scope.test.mjs`
  was missed by the prerequisite source-test audit. Prettier wrapped that sentence;
  the original HTML was restored byte-for-byte and excluded instead of changing
  the test or markup. This exclusion was discovered during verification and is
  identified separately in the inventory.
- Root README, build spec, notices and contribution guide: existing documentation
  and distribution text outside the source-formatting scope.

The R8 conformance receipts additionally hash 2,271 application/fixture paths.
These are historical execution snapshots, not immutable copies of current source:
they already had 60 stale pins in build/UI receipts and 14/12 in native/UI-R9
receipts before this change. Their receipt/report bytes remain excluded and
unchanged. Application formatting invalidates additional historical source pins;
it does not regenerate receipts or claim installed-runtime qualification.
Runtime-generated source/qualification manifests must be regenerated by their
normal qualification or packaging workflows for a future release.
