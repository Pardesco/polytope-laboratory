# Hyperbolic engine — Round 11 packages A + B

Implements four compact regular honeycombs `{5,3,4}`, `{4,3,5}`, `{5,3,5}` and
`{3,5,3}`, with rings `1000` only. Uniform ringings, ideal/hyperideal domains,
quotient construction, document persistence and UI mounting are outside this
phase-1 package. No shared integration files were changed.

Current developed-geometry acceptance follows the lead's recorded scale-aware
decision in design §9: `DEVELOPMENT_RELATIVE_GATE = 1e-12`. Absolute residuals
remain visible. The historical absolute-gate audit below is retained as evidence,
not as the current acceptance rule.

## Geometry

`engine/hyperbolic.py` exposes `J`, `lorentz_inner`, `coxeter_matrix`,
`gram_matrix`, `gram_symbolic`, `mirror_normals`, `reflection_matrix`,
`seed_point`, `regular_cell_template`, `lorentz_gram_schmidt`, `boost`,
`generator_residuals` and `local_analysis`.

Coordinates are float64 approximations in time-first order `(t,x,y,z)`,
`J=diag(-1,1,1,1)`, curvature −1. Matrices act on columns; serialized matrices
are flat row-major arrays of 16 numbers. The cell center is `(1,0,0,0)`.
Normals are rows with `N J Nᵀ = G`; reflections are `I − 2n(nᵀJ)`.
Integer Coxeter entries and symbolic Gram definitions accompany the numerical
API; they do not make coordinates exact. Every proper principal Gram submatrix
is checked positive definite, and the full signature is checked `(3+,1−)`.

Templates contain `vertices`, indexed `edges`, outward ordered `faces`, and
outward `facePlanes`. The finite parabolic group generated by mirrors 0,1,2
acts on the seed, seed edge and the finite 0,1 face orbit. These stabilizer
orbits define incidence without a convex hull. Vertex-stabilizer orbits on
the unit tangent sphere reconstruct the octahedral, icosahedral, icosahedral
and dodecahedral vertex links. Analysis measures dihedrals, equal edge lengths,
the number and angular gaps of cells around an edge, and p-fold face rotations.
Infinite total volume and Euler characteristic are returned as null.

The `{5,3,4}` test independently constructs inversion spheres using directions
`(0,±phi,±1)` and cyclic permutations, radius squared `sqrt(5)−1`, and centers
at distance `5^(1/4)`. It finds an orthogonal spatial change of basis and checks
both the independent vertex set and sphere inversions against Lorentz
reflections. No art-project modules, Blender or mathutils are imported.

## Development and pages

`engine/hyperbolic_orbit.py` develops cells by deterministic BFS across template
face reflections, composing on the right. Accepted words are relative face
generator indices, **not** four simplex-generator indices. First-discovery
IDs are contiguous integers local to the request epoch. Type `0` indexes the
single regular template. Accepted instances retain their own template labeling;
merges record the full candidate-to-target vertex permutation and target face.
Checkpoint replay reconstructs those permutations instead of trusting them.

Rounded Klein-center buckets only select candidates. The comparison itself
uses `T_existing⁻¹ T_candidate` in the existing cell's local Lorentz frame,
then matches every vertex bijectively. Adjacent buckets are searched. A center
collision with inconsistent vertex correspondence is an error.

Defaults: radius 3, depth 3, 256 candidate steps/page, ≤256 instances/page.
Maximums: radius 5, depth 12, 4,096 accepted cells, 50,000 visited adjacency
candidates, 256 MiB conservative working estimate, 2 seconds/page. A page also
stops after 2,048 neighbor updates to reserve message space. Budget values may
be lowered, never raised beyond the hard maximums. The working estimate is
`65536 + 16384*cells + 512*candidates` bytes; budgets below the initial
81,920-byte estimate are refused. This is an estimate, not measured process RSS.

`mode: "complete-depth"` expands unculled layers. `mode: "radius"` runs the
same unculled traversal, filtering publication by observer-to-cell-center
distance, and explicitly reports `sampled: true`. It makes no complete-radius
ball claim. `completedLayers` identifies fully discovered layers;
`ringCounts` beyond them are partial. `frontierCount` counts unexpanded cells,
including cells at the requested depth. Neighbor updates can refer to cells
outside the visible sample; absent targets must not be assumed visible.

`pageLimit`, `workPageLimit`, `bytePageLimit`, and `timeLimit` are resumable.
`depthComplete` finishes normally; `cellLimit`, `candidateLimit`, `memoryLimit`,
`wordLimit`, and `cursorLimit` stop without a cursor. Resource limits never
claim complete upper layers. Residual failure raises `GeometryError` and
publishes no partial result. Compositions use a one-generator suffix from an
already accepted parent; cold word reconstruction follows the same repaired
prefixes. The numerical audit below describes frame repair and point checks.

## Protocol

`engine/hyperbolic_protocol.py` exposes
`handle(op, params, *, manifold_handler=None)`. It returns one ordinary JSON
result, emits no streaming events and performs no file I/O. Errors use the
existing `GeometryError` path.

All operations take `source: {type:"honeycomb",pqr:[5,3,4],rings:[1,0,0,0]}`.

- `hyperbolic-create`: returns the design's `hyperbolic-space` descriptor with
  source, dimension 3, coordinateDimension 4, curvature −1, algorithmVersion
  `"1"`, provenance and `anchorPatch` containing the first page. Anchor geometry
  is capped at 1 MiB; smaller work/page budgets may be necessary for custom requests.
- `hyperbolic-patch`: takes `{source,epoch,anchor,radius,depth,mode,budget,cursor}`;
  `anchor` is `{word,observerMatrix}`. Defaults permit omitted optional fields.
  Returns `{sourceHash,epoch,anchorHash,templates,instances,neighbors,coverage,
residuals,nextCursor}`. Template type is its array index (currently `0`).
  Instances have `{id,type,word,matrix,quotientState:null,templatePermutation}`.
  Neighbors have `{cell,face,toCell,toFace,vertexPermutation}`; an unexpanded
  neighbor has null target/permutation and `status:"unexpanded"`.
- `hyperbolic-analyze`: returns the measured local analysis above.
- `hyperbolic-validate`: additionally takes `descriptor`. Rechecks source,
  dimensions, algorithm, template, instance words/matrices, metric gates,
  neighbor combinatorics and neighbor geometry where both endpoints are
  retained. Disposable boundary/coverage receipts are not trusted; returned
  `coverageReceiptTrusted` is false. Analysis is independently recomputed.

`budget` accepts integer `maxCells`, `maxCandidates`, `maxBytes`, `timeMs`,
`pageSize`, and `candidatesPerPage`. Unknown options are refused. The anchor
word identifies the address of the locally centered starting cell; it is not
multiplied into a growing global float64 position. ObserverMatrix maps the
observer frame into this anchor frame and must be future, proper and Lorentz
orthonormal within `1e-8`. Relative words and the anchor word each have a
256-generator limit. Long navigation address chunking belongs to E/D.

Cursor is plain JSON: `{version,sourceHash,anchorHash,budgetHash,epoch,state,
checksum}`. State contains accepted `words`, `types`, `next:[cell,face]`,
`candidates`, and `published`. All accepted words have been scanned for
publication (including culling). SHA-256 binds canonical source + algorithm,
anchor, all budgets, radius, depth, mode and epoch. Checksum detects accidental
edits; **it is not an authentication mechanism**. Restore replays and compares
the entire bounded deterministic BFS prefix, including counters, types,
incidence and identity; forged coverage cannot bypass replay. Replay counts
towards the page deadline and fails closed if verification exceeds it.

Requests/responses are capped at 4 MiB UTF-8; cursors at 1 MiB. Size, finite
numbers, collection lengths and nesting are checked before geometry arrays
are allocated. Oversized cursors produce explicit nonresumable truncation.
A 64 MiB LRU shares serialized responses and verified BFS prefixes. Response
keys include the canonical full request + operation + algorithm; prefix keys
include source/algorithm/anchor/budget hashes and epoch. Prefix object/container
and NumPy buffer storage is charged to the same byte limit as response bytes.
Before incremental replay, the untrusted cursor's types, counters and complete
accepted-word prefix must agree with the cached verified state; remaining
candidate steps and the final claimed frontier are still checked. Cache eviction
or worker death loses no essential state: a cold worker reconstructs from the
cursor. Returned objects are fresh copies. Cold replay still observes the
two-second deadline and can fail under load; warm-prefix reuse avoids repeating
all prior numerical checks on every page without requiring worker affinity.

## Scale-aware developed geometry — lead decision, 13 November 2026

`docs/HYPERBOLIC_DESIGN.md` §9 now records: “Lead decision 13 Nov 2026:
developed-geometry gates are t²-relative (1e-12) because absolute hyperboloid
residuals scale like t²·eps; absolute values remain reported.” This is an explicit
decision, not an automatic threshold adjustment.

Every developed metric/comparison uses the fixed dimensionless normalizers
below. The test is relative error **≤ `1e-12`**, including before correction.
`s ≥ 1` is the reported scale; the denominator is `s²`. At `s=1`, the comparison
is absolute `1e-12`. `GENERATOR_GATE=1e-12` absolute and `EDGE_GATE=1e-7`
relative are unchanged. `DEVELOPMENT_GATE=1e-8` remains solely for the existing
absolute observer-input validation and finite pinned-domain certificates.

| Check                                                           | Absolute error                              | Scale s                                                          |
| --------------------------------------------------------------- | ------------------------------------------- | ---------------------------------------------------------------- |
| Point metric, before/after frame repair and after normalization | `abs(XᵀJX+1)` for each point                | `max(1,abs(t))` for that point; divide before taking the maximum |
| Transform metric, before/after repair                           | `max abs(MᵀJM−J)`                           | `max(1,max abs(M))` of the underlying frame                      |
| Matrix reconstruction and frame correction                      | `max abs(A−B)`                              | `max(1,max abs(A),max abs(B))`                                   |
| Candidate cell-center comparison                                | `max abs(centerA−centerB)`                  | `max(1,abs(tA),abs(tB))`                                         |
| Full vertex correspondence and retained neighbor correspondence | `max abs(A−B)` over the compared point sets | `max(1,max abs(tA),max abs(tB))` over both complete sets         |

The full vertex permutation is still found in a common local Lorentz frame.
Its geometry is then checked using the matched vertex sets in their shared
anchor frame, with the point-set scale above. Rounded buckets never establish
identity. An inconsistent permutation or incidence is still rejected.

Receipts preserve each absolute field and add `<field>Relative` and
`<field>Scale`, including all pre-correction point/transform checks, frame
corrections, merge center/vertex discrepancies, retained matrix reconstruction,
and retained neighbor discrepancies. Aggregate maxima may occur on different
points/candidates; the reported maximum scale is not necessarily the scale at
the maximum relative error. Point metrics normalize each point independently,
so one distant point cannot dilute a corrupted near-anchor point. The overall
`coordinates` triple takes maxima over the before-repair, before-normalization,
and normalized checks. Failed checks include the same triples in their error.
Point normalization's component change is also reported as a point-set
`pointCorrection` triple; its acceptance checks are the pre/post point metrics
and unchanged edge-spread gate. It does not replace the authoritative instance
matrix/template geometry, whose unnormalized points are independently checked.

Timelike-first Gram–Schmidt now uses standard-library Decimal intermediates
when the largest frame entry exceeds 4. Precision is at least 32 decimal digits,
increasing with scale (`max(32, 2*ceil(log10(scale))+20)`); output and all gates
remain float64. This prevents float64 projection arithmetic from introducing
extra drift on words returning toward the anchor, where the new rule is
stricter than the old absolute `1e-8` gate. No dependencies were added. Odd
reflection-word parity is factored out for SO+ repair and restored as before.

The shared helpers in `hyperbolic.py` are `point_metric_residual`,
`matrix_metric_residual`, `point_discrepancy`, `matrix_discrepancy`, and
`record_residual`. Honeycomb pages, retained-geometry validation, and manifold
lift development use the same definitions. Manifold finite-domain pairing
certificates retain their separate existing absolute tolerance. Its analysis
receipt labels `gates.development` as relative `1e-12` and
`gates.finiteDomainAbsolute` as `1e-8`. Neither honeycomb `observerMatrix` nor
manifold local-pose input validation is relaxed; their messages still state
the absolute `1e-8` frame check.

## Historical depth-four numerical audit — former absolute gates

At the time of this historical audit, gates were **absolute `1e-8`** for coordinates/transforms/merges and
`1e-7` for edge spread. The follow-up improves drift but does **not** make the
entire unrecentered `{5,3,5}` depth-four patch acceptable on this machine.

After each one-generator composition, the engine gates the uncorrected
coordinate error, transform metric error and edge spread. It then applies
timelike-first Lorentz Gram–Schmidt and gates the repaired transform and its
raw developed points again. Only points passing these pre-normalization gates
are normalized as `X/sqrt(-<X,X>)`, with future time checked. Normalized points
and their edge spread must also pass. The existing `coordinates` receipt is
the maximum of all three absolute coordinate checks, never just the projected
value. Out-of-gate points are not normalized or accepted.

Receipts additionally record `coordinatesBeforeRepair`,
`coordinatesBeforeNormalization`, `coordinatesNormalized`,
`transformMetricBeforeRepair`, `transformCorrection` (maximum absolute matrix
entry change), `pointCorrection` (maximum absolute component change),
`coordinatesRelative`, `transformMetricRelative`, `centerDistance`,
`maxVertexDistance`, and `maxVertexTime`. Relative values are diagnostics only.
Point normalization is used for engine edge/residual checks; published geometry
remains the template plus instance matrix, whose **unnormalized** points are
separately gated. No change to the viewer/protocol geometry convention is implied.

Reflection words have determinant `(-1)^wordLength`. Forcing every stored frame
into SO+ would silently change vertex correspondence on odd words. Instead,
factor out the known spatial parity `D=diag(1,1,1,(-1)^n)`, repair `M D` in SO+,
then restore `D`. Frames remain future Lorentz isometries with the original
handedness. Tests check parity and metric error for every accepted depth-four
frame. Rebuilding starts at the longest accepted word prefix, not from a
distant anchor product; cold and warm reconstruction follow identical repairs.

nothing. Previously accepted pages remain usable.

To separate drift from arithmetic, the probe also uses 70-digit Decimal
arithmetic on the **stored float64 inputs**, not on claimed exact geometry:

- Exact evaluation of stored matrix metric: max `1.64961e-11`.
- Unrounded high-precision product `M V`: max point norm error `4.84869e-10`.
- Float64 matrix-vector rounding: max component change `7.04332e-13`.
- Exact evaluation of those rounded float64 points: max norm error
  `1.01966e-8`, already above the gate.
- Ordinary float64 norm evaluation: max `1.49012e-8`.

Thus repairing only the matrix cannot guarantee this absolute point gate:
forming and evaluating coordinates contributes the dominant error here.
The scale is `t² * eps`: `3.88285e-9` at the rejected candidate and
`1.69382e-8` at the diagnostic prefix's farthest `t≈8734.041`. Cancellation in
`−t²+x²+y²+z²` and coordinate quantization are already of the requested
absolute tolerance. The raw norm remains authoritative; no relative acceptance
criterion or looser threshold was substituted. These observations establish
the failure of this float64 repair strategy, not a proof that every possible
coordinate algorithm must fail. Local publication frames/rebasing or any
scale-aware acceptance rule require a lead design decision.

## Limits and integration notes for E

- Wire the four op names to `hyperbolic_protocol.handle(op, params)` in server
  dispatch and the desktop allowlist. Add patch/analyze/validate to warm reusable
  operations. Keep create/source changes in `commitOperation` history/replay;
  exploration pages are view/cache state and use `markDirty` at gesture end.
- No UI is mounted by this package. E/F should connect the four regular library
  presets to create; D consumes the page contract above. Intended controls are
  `hyperbolic-model`, `hyperbolic-radius`, `hyperbolic-layers`,
  `hyperbolic-pause`, `hyperbolic-explore`, and `hyperbolic-home`. No ring builder.
- Route manifolds through `handle(op, params, manifold_handler=callback)`.
  Callback receives the unchanged op/params and owns pinned-domain validation,
  all manifold-specific budgets, cache and cursor semantics. Honeycomb code
  deliberately refuses manifold sources without that callback.
- Branch on document kind before all Euclidean validators/history/render paths.
  Save source recipe and bounded anchor geometry in schema v2. The first page's
  `nextCursor` is disposable; move it into the generation cache and strip it
  from saved anchor geometry. On reopen, validate retained geometry and restart
  generation; do not trust persisted coverage receipts.
- Check epoch, sourceHash, anchorHash and document revision before publishing.
  Apply neighbor rows as updates keyed by `(cell,face)`. A later row replaces an
  earlier explicit unexpanded row. Preserve the full vertex permutation.
- Keep the anchor address separate from relative instance words; D/E must
  transport observer pose consistently during rebase and chunk saved addresses.
  No automatic navigation/rebase is implemented here.
- Depth 12 is an input ceiling, not a guarantee that a distant unrecentered
  patch passes every check. All four presets now publish at depth four under
  the recorded scale-aware decision (three stop at the cell cap). Future-point,
  frame-repair, relative metric and unchanged edge-spread checks can still
  reject distant geometry. Retain the previous complete page on failure.
- Default work-limited pages are byte-identical across cold-cache replay in
  tests. A real wall-clock timeout can select a different checkpoint under
  different machine load; exact page boundaries under time exhaustion are
  not deterministic. Accepted IDs/order and resumed BFS remain deterministic.
  No desktop startup/frame-rate or hard real-time performance claim is made.
