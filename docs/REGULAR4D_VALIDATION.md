# Numerical validation of the sixteen regular 4-polytopes

`engine/regular4d_validation.py` version 0.1.0 independently validates the six existing convex references and ten attributed Miratope star references. It preserves the complete current source snapshot, original coordinates, ordered faces, cell membership, units, RGBA and interpretation. Returned evidence is separate from the model. No source hull, repair, inferred star interior or exact certificate is introduced.

The fixed identity crosswalk uses Schulte's classical symbol/count tables and flag-transitivity definition, together with Bowers' names, cell types, vertex figures and dual pairings. These public references provide mathematical expectations; they are not an executed Stella 6 catalog. [Schulte, tables 18.1.1 and 18.2.1](https://www.csun.edu/~ctoth/Handbook/chap18.pdf), [Bowers, regular polychora](https://www.polytope.net/hedrondude/regulars.htm).

`validate_catalog_regular4d(model, key)` accepts an explicit existing catalog key and returns numerical evidence. It verifies every source incidence rank, prescribed polygon winding, equal edge lengths, common vertex radius, four incidence-preserving flag reflections and their mirror Gram angles. Their orbit must reach every actual source flag. The complete current snapshot hash, model ID and geometry fingerprint bind the evidence. `verify_catalog_model_receipt(model, receipt)` reconstructs and compares the entire receipt, including all permutation maps and source attributes.

The coordinate tests use binary64 arithmetic, normalized tolerance `1e-8`, at most 600 vertices, 1,200 edges, 1,200 faces, 600 cells and 14,400 flags. Snapshot bounds are 32 MiB, 200,000 values and depth 64. Unpaired Unicode, unsafe JSON integers, stale geometry fingerprints and invalid units or RGBA are rejected. These are numerical regularity proofs within explicit tolerance; `certified` remains false. No exhaustive enumeration of arbitrary orthogonal spanning-frame images is claimed.

`analyze_regular4d(model, identity_name, source_sha256=None)` supports independently supplied literal realizations. A raw source hash can be supplied only by a reader that actually checked authorized source bytes. The catalog-model API deliberately does not infer such ownership from editable provenance. `qualify_catalog(directory)` checks the pinned attributed manifest, all sixteen raw reference hashes before and after validation and ten reciprocal dual relations with complete rank-transposing incidence maps.

`scripts/qualify-regular4d-catalog.py --output <evidence.json>` records actual registered models and their receipts in addition to the independent source-reference qualification. This reads catalog assets and writes only the chosen evidence file. The proof includes implementation/importer source hashes; running that compiler in a frozen bundle requires retaining its raw validation module beside the three importer provenance files.

Catalog metadata adds primary names, aliases, symbols, cell/vertex-figure types and dual keys to the same existing entries. Provider keys, license attribution, acquired manifests and geometry bytes remain unchanged. The server generation wrapper applies `regular4d_metadata(key)` to builtin generated models; their original generator registry is untouched. The strict read-only server operation is `regular4d-validate` with `model` and exactly `params: {key}`. Analyze exposes numerical verification for these catalog models, with a flag-orbit summary rather than an exact certificate.

`scripts/regular4d-catalog-smoke.cjs` prepares real desktop qualification of all sixteen entries: symbol/alias search, native loading, independent literal incidence comparison, per-source numerical receipts, representative Save/Open and full RGBA/unit inheritance. Its `--self-test` runs only the headless proof generator. Actual desktop and packaged results remain separate release evidence. The historical development verifier, crosswalk, negative fixtures and receipt are preserved without modification. Original LIB-04 closure still requires reviewing the mounted and packaged evidence; this module does not close unrelated regular-star editing domains or the full specification.
