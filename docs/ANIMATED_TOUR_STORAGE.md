# Animated tour storage

Native tours retain both legacy instant envelopes (`version: 1`) and animated envelopes (`version: 2`). Both have exactly `version`, `events` and `cursor`; events have exactly `id`, `state`, `duration` and `transition`. A state's complete model, view, notes, units, RGBA, offline metadata and inert operation lineage remain retained snapshots. Native project validation still checks incidence and certificates and rebuilds derived caches and measures; it does not replace a source boundary with a Hull.

Version 1 retains the literal transition string `instant`, its existing load/save behavior and instant evaluator. Version 2 uses an outgoing transition option record. The event duration is a hold of at most 3,600 seconds; the transition duration is separate. The last transition is saved even though it runs only during looping playback.

The authoritative presentation schemas are [transitions](../ui/transitions.mjs), [animation tracks](../ui/animation.mjs) and [the absolute timeline](../ui/animated-tour-timeline.mjs). Native [tours](../engine/tours.py) accepts the eight methods `instant`, `sideways`, `orbit`, `shrink-grow`, `explode-grow`, `shrink-implode`, `explode-implode` and `combination`. Transition fields are version, method, duration, easing, angle, distance, tilt, orbits, spin, explosionSize, direction and components. Missing options use the frontend defaults for validation; native storage preserves the supplied record. UI normalization fills the same defaults explicitly.

Transition duration is 0–60 seconds, zero for instant and positive for the other methods. Easing is linear, smoothstep or smootherstep. Angle is −360–360 degrees, tilt −180–180, distance/orbits/spin 0–100, explosion size 1–100, and direction ±1. A combination contains one to four distinct supported component methods and at most one explosion/implosion component. Unknown methods, fields or track kinds are refused rather than discarded or converted to instant.

The native APIs remain `tour_documents(tour)` and `validate_tour(tour)`; `validate_tour_transition(value)` additionally returns a detached checked transition record. Existing project, standalone `validate-tour`, `save-tour` and `load-tour` paths call these helpers. `validate_tour` leaves caller data unchanged. Existing animation validation preserves supported rotation, section-depth, explosion and face-net folding tracks.

The immutable [UI storage core](../ui/tour.mjs) keeps the event version through add, replace, duration, select, move and delete. `setTourTransition(value, index, transition)` explicitly upgrades a legacy tour to version 2. A mixed merge also upgrades to version 2, retaining every snapshot and the established deterministic ID collision policy. `tourDuration` and `tourEventStart` include outgoing transition durations except the final transition. `evaluateTour` refuses version 2 explicitly; use the animated timeline to avoid losing its saved transitions.

Storage bounds remain 100 events, 32 MiB per event, 128 MiB total, nesting depth 64 and eight million JSON values. Malformed UTF-8, nonfinite numbers, oversized numeric view inputs and unsupported records produce structured native errors. All retained events are checked, including those not initially shown.

Storage acceptance does not establish renderability. A valid normal explosion track combined with a radial explosion transition, folded explosion, generalized directions, or a positive interval lost at cumulative Float64 resolution can remain readable while renderer/timeline preflight refuses execution. No complete export, whole-surface projection, video timing or full ANIM-03 parity claim follows from storage validation.

Focused native evidence includes exact ordered pentagram cycles and a hand-authored tesseract's full face/cell incidence, RGBA and units through Node JSON and native project save/open; standalone tour import/export; transition options and saved tracks; malformed unused events; and atomic refusal that preserves an existing standalone file. Frontend tests cover version-preserving edits, explicit migration, mixed merges, snapshot ownership and the unchanged legacy behavior alongside the timeline and renderer suites.
