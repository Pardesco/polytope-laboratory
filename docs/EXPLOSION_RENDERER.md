# Source-referenced explosion renderer

`Viewer.setExplosion(geometry|null)` accepts the validated automatic presentation payload from `explosionGeometry`. It returns `{applied, supported, diagnostic}` synchronously. A valid nonzero convex-source payload renders independent source faces in 3D or source cells in 4D. Null and exact zero use the existing original pipeline, with identical point/edge/surface/highlight buffers, opacity, depth behavior and source picking. Clearing a nonzero explosion restores that pipeline.

The actual viewer advertises `supportsExplosion=true`. A caller preparing playback or an export must inspect the status and the subsequent `setDisplay` diagnostics; an invalid payload leaves the original geometry visible with an explicit error, which must not be described or captured as a successful explosion. Unsupported generalized or compound sources, mismatched source identity/normalization, invalid translated coordinates, incomplete source incidence and resource-cap failures are rejected before the instance presentation is installed. Derived nets have their own representations and reject this explosion payload.

The original mathematical `this.model`, source fingerprint, source coordinates/incidence and source-indexed `this.projected` remain intact. The renderer uses `prepareExplosionDisplay` from [VIEWER_EXPLOSION.md](VIEWER_EXPLOSION.md) to build separate instance vertices, edges and face/cell triangle owners. It normalizes translated points with the original source mean and radius, never by fitting the exploded cloud. Every repeated original vertex/edge maps back to its source ID; virtual fill, clipping and spherical tessellation samples remain display points. The observer's Fit action includes the displayed instances and finite projected pieces and changes only the observer camera.

Visible instance points and full-size boundary edges feed ordinary point/line buffers or bounded instanced spheres/cylinders. Picking uses their actual screen paths and original source IDs. Face/cell ray picking uses the displayed surface patches; independent 4D cell instances retain their unique active owner. Source-vertex highlights cover all corresponding visible instances, with hidden or clipped instances excluded from the visible cloud. Repeated hits deduplicate the same source entity using the existing deterministic ambiguity-cycle contract. This is visible-mask/frustum qualification, not a new pixel-depth occlusion guarantee.

For 4D cell shrink, each cell surface interpolates about that cell's translated source-vertex mean before display frame, six incremental rotations and projection. Its source boundary edges and vertices retain their full-size translated positions. Manual source cell visibility/isolation and observer-facing masks constrain each independent cell owner, including duplicated faces originally shared between cells. Source face RGBA takes precedence over source cell RGBA; cell palettes retain the original cell ID. Existing opacity and opaque/translucent depth rules apply.

The saved SO(4) display frame and incremental angles apply once to all instance vertices and virtual surface points. Stereographic projection uses the existing adaptive S3 segments/patches and analytical curved normals; adjustable 4D perspective uses actual near-clipped segments and barycentric source patches. Their edge indices address instance buffers until the renderer maps them back to source edge IDs for picking and cylinder records. Their existing caps, finite-image bounds and clipping diagnostics remain applicable. Ordinary 3D/orthographic presentation uses projected instance triangles and regenerated finite normals.

For observer-facing 4D cells, the original verified source plane `(n,h)` is retained. A cell translation `delta` in source units changes its normalized plane offset to `h + n·(delta/sourceRadius)`. Only a fresh classification wrapper receives that offset; the saved native plane cache and resolved source planes are unchanged. The proper display frame/angles rotate its normal afterward. Orthographic direction classification is translation-invariant; finite-eye classification uses the actual perspective eye or S3 pole and can change as a translated cell crosses the observer plane. These planes describe presentation-cell supports, not a newly filled exploded solid.

`setDisplay` returns `explosionApplied`, `explosionDiagnostic`, and either null or `explosionCounts` containing visible instance vertex/edge/face/entity counts, rendered triangle count, amount and direction. Those counts describe presentation duplication; the project's mathematical model counts remain the original counts. Primitive counts can be lower when displayed edges collapse, clipping omits points/pieces or sphere/cylinder budgets require their explicit point/line fallback.

Eight actual-renderer fixtures in `tests/explosion-viewer.test.mjs` passed: exact null/zero/clear compatibility; original-normalization face instances and repeated source picks/highlights; independent 4D owners/source alpha/normals; translated finite-eye facing without cached plane changes; translated-center shrink and masked owner picks; once-only frame/perspective/S3 paths; malformed/generalized/stale/capped fallback diagnostics; and Fit enclosing the translated instance cloud without renormalizing the source. The combined instance-helper and existing renderer/camera/projection suite passed 118 tests; all eight focused renderer fixtures passed, including the additional Fit case. These are real Three.js buffer/material/picking tests without a WebGL context. No matching built UI, Electron/export regression, packaged run or installed external baseline is claimed by this renderer-core evidence yet.
