## Collector and receipt contract

[scripts/qualify-lib04-gate.py](../scripts/qualify-lib04-gate.py) is new and unmounted. It never modifies the ledger, source or runtime and never launches Electron. Its only executable validation is the supplied candidate's native JSONL engine, with hidden subprocess flags on Windows. Native and frontend qualification receipts must cover exactly their current complete scopes, with all input hashes unchanged. Actual engine resource membership/bytes and every packaged desktop/dist ASAR entry are rechecked. Original spec bytes and all 73 exact acceptance rows are retained in the output.

The collector requires the new outer runner's `qualificationScriptSha256` / `qualificationScriptUnchanged` and per-suite `scriptSha256` / `scriptUnchanged` fields. Historical development receipts lacking these fields cannot qualify. The five desktop workflow descriptions and fixed sixteen-key/symbol/count/flag domain must all match. The full reference qualification, dual maps, registered receipts, loaded receipts and saved complete source snapshots are recomputed from qualified sources. Finally, sixteen requests to the actual candidate engine must return byte-value-equivalent complete receipt objects in order. No summaries/counts-only shortcut is accepted.

```powershell
python -B scripts/qualify-lib04-gate.py `
  --unpacked-root release/0.20-candidate/win-unpacked `
  --native-source-proof artifacts/native-development-0.20.0.json `
  --native-bundle-proof artifacts/native-bundle-candidate-0.20.0.json `
  --frontend-proof artifacts/frontend-candidate-0.20.0.json `
```

Paths are explicit, existing and strictly repository-contained; the candidate must be beneath `release/`. Evidence belongs to the actual outer suite folder. Output defaults to a new `artifacts/lib04-gate-<version>.json`; existing receipts are never overwritten. The actual candidate and packaged proofs must exist before running this command. This audit does not supply a fake passing release receipt.
