## Changes

Rotation no longer converts the non-pose view, notes and annotation document to
JSON on every ownership check. A completed full refresh captures detached literal
snapshots; angle-only displays compare current values against those snapshots.
Immutable strings, including embedded PNG base64, retain their values without
repeated encoding. Nested records and arrays are copied, so in-place edits cannot
change the stored receipt. Annotation contents are compared once inside the view
instead of being serialized both there and separately.

The state, source, renderer model, project, document, history cursor/states,
annotation identity, net, cell net and layer identity checks remain. Comparisons
still visit nested literal annotation/source records. This does not promise zero
work proportional to record count. Unsupported snapshot values conservatively
force a full refresh. Explicit empty annotation documents stay explicit.

The existing pose-only exception stays restricted to the audited angle callers.
Pending/failed refreshes cannot authorize it. Asynchronous stereographic
publication rechecks ownership. Ordinary displays, content edits, native
publication and capture retain their full validation paths. No source hash,
fingerprint, ID or count replaces those checks.

Native convex intrinsic 3D **sizing** evaluation now retains one prepared plan per
worker process. Its key is the complete canonical JSON of the bounded, validated
source, settings and notes/effective-unit context. It compares the entire key
string, without a digest shortcut. Every request also retains the existing full
comparison of the caller's preparation against the native preparation. Source
metadata, colors, embedded attributes, units, center, radius and playback
settings all participate. A miss reconstructs and checks the plan normally.

The retained key is limited to 2 MiB and the retained preparation's serialized
representation to 4 MiB. Larger eligible requests compute normally without
caching. One different key evicts the previous entry. Cached preparations are
detached from caller records, and frame outputs do not alias retained data.
Cancellation/worker retirement loses the cache safely. These are serialized
record limits, not a measurement of total Python process memory.

Only the read-only convex 3D `SizingPlan` is admitted. Generalized sizing and all
other methods keep their original reconstruction paths. Some other plans retain
additional intermediate state, so this change does not generalize their reuse.
The geometry algorithms, parameterization and literal endpoints are unchanged.

Repeat native analysis can also reuse a report for a complete unchanged source.
The original protected analyzer runs on every miss, including geometric
validation and intrinsic measure recomputation. A bounded four-entry LRU cache
compares full literal JSON plus analyzer identity. Changed/invalid sources and
forged reports or measure scalars cannot reuse old data. The limits are 2 MiB per
key, 1 MiB per result and 8 MiB total serialized records. Explicit validation and
first analysis retain their original computations; cold misses add bookkeeping.
See [the analysis reuse evidence](NATIVE_ANALYSIS_REUSE.md) for the proof, exact
source/resource policy and raw measurements.

The packaged morph benchmark now honors an explicit unpacked executable and
historical version, disables development Python for packaged runs, and checks
native saved source/notes/non-morph view/settings preservation across playback.
The rotation series/comparison tools accept explicit baseline/candidate versions;
their original 0.27.19/0.27.20 defaults and write-once receipts remain intact.
Optional `--navigation` profiles four revisits to each of three existing model
documents before annotation edits. Comparison preserves separate first-draw and
settled timings and aggregates independent run medians. The phase's actual
desktop execution is pending.

## Truncated-tetrahedron scaling investigation

The native source bound is 0.5527707983925668. Radius 1 produces a reciprocal
bound of 3.464101615137754. Automatic reciprocal radius 0.3994636211547385 gives
the reciprocal the same bound as the source.

Sizing deliberately displays two layers with scales `1-t` and `t`. With matching
endpoint bounds, their combined bound relative to the source is:

| Ratio | 0 | 0.25 | 0.5 | 0.75 | 1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Relative bound | 1 | 0.75 | 0.5 | 0.75 | 1 |

A new real-Viewer/native-frame test confirms this behavior while the camera,
source normalization center/radius and mathematical source stay fixed. The guide
now explains the smaller midpoint. This identifies the defined sizing behavior;
it does not establish which settings were used in every earlier user report.
No per-frame renormalization or unrequested change of trajectory was introduced.
Other methods and visible-window playback still need normal-session observation.
